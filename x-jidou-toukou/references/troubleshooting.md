# 困ったときの直し方

実際に組み立てたときに起きたことと、その直し方。「（想定）」が付いた行は、まだ起きていないが起こりうるもの。

## X に投稿できない（GitHub Actions のログで分かる）

| ログに出る言葉 | 原因 | 直し方 |
|---|---|---|
| `403` `client-not-enrolled` / `must use keys and tokens from a developer App that is attached to a Project` | アプリが古い無料プラン（Free / Standard Basic）のプロジェクトにつながっている。クレジットを買っても直らない | console.x.com → アプリ → プロジェクトアクセス →「管理」→ Pay Per Use のプロジェクトの「ここに移動・Production」。合言葉の作り直しは不要 |
| （想定）`402` / `credits` / `insufficient` | クレジットの残高切れ | console.x.com でクレジットを買い足す。自動チャージを勧めるかは本人に任せる |
| （想定）`403` `oauth1-permissions` / `not permitted to perform this action` | 合言葉が「読み取りのみ」の権限で作られている | アプリの権限を「読み取りと書き込み」にしてから、アクセストークンを作り直し、`gh secret set` で入れ直す |
| （想定）`401` `Unauthorized` | 合言葉の入れ間違い・作り直し後の入れ忘れ | 4つを `gh secret set` で入れ直す。コンシューマーキー＝API_KEY/API_SECRET の対応を確かめる |
| （想定）`403` `duplicate content` | 同じ文章を最近投稿している | queue.md の該当の投稿を直すか消す |
| （想定）`403` で文字数の話 | Premium でないのに長い投稿 | 型を短くする（140字以内）か、Premium に入る |
| （想定）`リプライだけ失敗しました` | 本投稿は出て、リプライだけ失敗 | 本投稿は posted.md に記録済み（翌日に二重投稿はされない）。補足は手で返信してもらう |

失敗した日は、queue.md の投稿はそのまま残る。直したあと、手動で「本番（投稿する）」を動かせば出る。

## 投稿案が入らない（クラウドの Claude の側）

実行の記録は `RemoteTrigger` の `list_runs` → `get_run_log` で読める。最後の報告に理由が書いてある。

| 症状 | 原因 | 直し方 |
|---|---|---|
| 「24時間以内の発表が見つからない」で何もせず終わる | 条件が厳しすぎる（週末は発表が少ない） | news_routine.md の探す期間を72時間にし、調べる会社を列挙して「1つ2つで決めない」と書く（ひな形は対応済み） |
| `getaddrinfo ENOTFOUND openai.com` など、公式サイトが開けない | クラウド環境のネットワークが制限つき | claude.ai/code →「☁ Default」→「クラウド ＞」→ Default の歯車 → ネットワークを Full |
| （想定）`claude/…` という別の枝に書き込まれ、main に入らない | 保管場所への書き込みが制限されている | routine の編集画面（claude.ai/code/routines → 鉛筆）→ Permissions → その保管場所の「Allow unrestricted branch pushes」に印を付ける（今回は不要だったが、環境によっては要る） |
| リポジトリが見えない・取り込めない | GitHub の「Claude」アプリに、その保管場所の許可がない | github.com/settings/installations → Claude → Configure → Repository access に追加 |
| 公式ページで確かめられず「ネタなし」で終わる（2026-10-12 に起きた） | 公式サイトが 403 で開けない日に、報道で見つけたネタまで捨てていた。「学校向けでない」という理由でも外していた | news_routine.md に「公式が開けないときは大手報道2つ以上で一致していればよい」「読者向けの分野でなくても、知っておくとよい話なら選んでよい」を足す（ひな形は対応済み）。探す期間を広げたり、ふり返り型で無理に出したりはしない（本人の希望：ネタがない日は出さない） |
| queue.md の説明文が壊れる | Claude が queue.md を直接書き換え、説明文の中の `---` を区切りと間違えた | news_routine.md で「`python post_next.py --add 下書き` を使い、queue.md を直接書き換えない」と指示する（ひな形は対応済み） |

## 投稿の中身がいまいち

| 症状 | 直し方 |
|---|---|
| 大きなニュースを見落とす | 「候補を5件以上、会社名・内容・発表日の一覧にしてから選び、一覧を報告に含める」と指示する（ひな形は対応済み）。報告の一覧を見て、足りない会社を指示書に足す |
| 専門用語が読者に伝わらない | 読者の説明と、言い換えの例（「トークン（AIが文章を数える単位）」など）を指示書に書く |
| 「〇〇の一言：」のような見出しが付く | 「見出しは付けない」と型の中に書く |
| 古い話題が出る | 試しの投稿案や、失敗した日の投稿案が下にたまっている。queue.md を見て消す |

## 画像が付かない・おかしい

| 症状 | 原因 | 直し方 |
|---|---|---|
| ログに「画像が見つかりません」 | 投稿案の `画像:` 行のファイルが commit されていない | 5時の係の報告と images/ を見る。画像なしで出すなら、その行を消す |
| ログに「画像の送信に失敗しました」 | X 側の問題（合言葉・残高・画像が大きすぎる 5MB 超 など） | 「画像を送れるか確認」モードで切り分ける |
| 5時の報告に「ページを開けませんでした（403）」 | サイトがロボットを断っている（openai.com はいつもこう） | 想定どおり。fal で図を作る流れになる |
| 「FAL_KEY が設定されていません」 | クラウド環境に fal のキーがない | claude.ai/code → Default の歯車 → 環境変数に `FAL_KEY=…` を貼ってもらう |
| （想定）`playwright install --with-deps` が失敗する | クラウド環境で追加の部品が入れられない | `--with-deps` を外して試す。だめなら fal だけで運用する |
| fal の図に変な文字が入る | 画像生成AIは文字が苦手 | 説明に「no text, no logos」を入れる（ひな形は対応済み） |

## 投稿案（queue.md）を見られない

| 症状 | 原因 | 直し方 |
|---|---|---|
| ブラウザで queue.md の URL を開くと「404 This is not the web page you are looking for」 | GitHub にログインしていない。非公開の保管場所は、ログインしていない人には「存在しない」ように見せるため404になる。右上に「Sign in」が出ていればこれ | 右上の「Sign in」から、保管場所の持ち主のアカウントでログインして開き直す。一度ログインすれば次からはそのまま開ける |
| ログインしているのに404 | 別の GitHub アカウントでログインしている | 右上のアイコンでアカウント名を確かめ、持ち主のアカウントに切り替える |

## GitHub 側

- 毎朝の自動実行は、GitHub の混雑で数十分遅れることがある
- 60日間リポジトリに変化がないと、GitHub が毎日の自動実行を止める。Actions の画面で「Enable workflow」を押せば再開する
- 古い自動投稿の仕組み（別名のワークフロー）が残っていると二重投稿になる。`.github/workflows/` に post.yml 以外がないか見る
